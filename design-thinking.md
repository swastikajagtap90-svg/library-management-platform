# Design Thinking Report

## 1. Empathize

Understand the workflows and difficulties of the people who use or manage an academic library.

### Stakeholder groups

- **Students:** Need to find books quickly, know availability, and avoid unexpected overdue fines.
- **Faculty members:** Need reliable access to academic resources and clear borrowing information.
- **Librarians:** Need accurate catalog records and efficient issue/return processing.
- **Library administrators:** Need reliable utilization data, audit trails, and reports.
- **System administrators:** Need secure, maintainable, and observable systems.

These are initial personas and assumptions. They should be validated through interviews, observation, and usability research.

## 2. Define

### Problem statement

Library members can experience delays when locating, reserving, borrowing, and returning resources when records and workflows rely on manual tracking. Library staff may also lack centralized, timely visibility into inventory, overdue items, and usage.

### Design challenge

How might we help library members complete common tasks quickly while enabling staff to maintain accurate records and understand library operations?

## 3. Ideate

Potential ideas to evaluate include:

- Multi-field book search and clear availability status
- Digital membership profiles and role-based access
- Streamlined checkout, renewal, and return workflows
- Automated due-date reminders
- Transparent fine calculation
- Inventory and usage dashboards
- Exportable administrative reports

Ideas should be prioritized based on user value, feasibility, risk, and implementation effort.

## 4. Prototype

Create low-fidelity wireframes for:

1. Login and profile
2. Student/faculty book search
3. Book details and availability
4. Librarian checkout and return dashboard
5. Admin analytics and reporting

The first prototype should focus on completing the main user tasks with minimal friction rather than visual polish.

## 5. Test

Test prototypes with representative students, faculty, and library staff.

### Suggested usability tasks

- Find a particular book and confirm whether it is available.
- Check a book out and identify its due date.
- Find an issued book and process its return.
- Identify an overdue item and explain how its fine was calculated.
- Generate a basic inventory or usage report.

### Measures to collect

- Task completion rate
- Time required per task
- Number of errors or requests for assistance
- User-reported clarity and satisfaction

Collect actual measurements during testing; do not report target values as achieved results.

## IBM Design Thinking connection

- **Focus on user outcomes:** Measure whether users can find and borrow resources efficiently, not only whether a search feature exists.
- **Restless reinvention:** Use feedback and operational data to refine the experience.
- **Diverse empowered teams:** Involve product, design, development, QA, database, and operations roles.

## IBM Loop

**Observe → Reflect → Make**

- **Observe:** Study user interactions, feedback, and operational friction.
- **Reflect:** Analyze findings and agree on the most important problem.
- **Make:** Build and test a small improvement, then repeat the loop.
